# 学内施設使用許可願生成マシーン（横浜キャンパス）

既存GAS／Excelの**申請書作成機能**を、サーバー処理なしの静的Webアプリに移植しました。予約の空き確認・確定・申請の送信は行いません。元の資料は変更していません。

## まず使う（Windows）

現在の作業環境ではビルド済みです。

1. [起動.cmd](<起動.cmd>)をダブルクリックします。すでに起動中なら不要です。
2. **http://127.0.0.1:4173** をChromeなどで開きます。
3. 教室カードの後にある「学生責任者情報の入力」で氏名・学籍番号・携帯電話番号を入力します。
4. 使用目的、申請日、使用日時、教室、人数を入力します。使用目的は空欄のままでも、PDF保存時に「本会の対面活動を実施するため」を補います。
5. 必要に応じて日時を追加します（最大9件、団体・責任者・使用目的は共通）。
6. 左の申請書プレビューを見ながら編集し、「PDFを保存」を押します。スマホでは「申請書プレビュー」で表示を切り替えられます。

停止は起動用の黒い画面で **Ctrl+C**。ポートが使用中と表示された場合は、すでに起動している画面を使うか、元の起動用画面を閉じてから再実行してください。画面が古い場合は再読み込みしてください。HTMLを直接ダブルクリックする方式では利用できません。

Node.jsが見つからない場合はNode.js 24 LTSをインストールしてください。この端末ではDeepSeek Harness付属Node.jsも自動的に候補とします。

## 機能

- PC／Android Chromeを想定したレスポンシブ画面。デジタル庁風の色・余白・入力部品を独自実装。
- 左に申請書プレビュー、右に入力カード。入力欄のフォーカス中だけ淡い赤で強調し、周囲は200msで自然に暗転・復帰します。動きを減らすOS設定にも対応。
- 日時・教室は1件ずつ独立したカード。件数は`1/9`で表示。
- 42教室の選択、ROOMLISTの掲載写真を全点収録したギャラリー。写真は縦横比を保ったまま横スクロール・スワイプ・マウスドラッグでき、クリックで拡大。
- 時刻は元のブラウザ標準入力（1分刻み）。
- 写真・確認モーダルは×・Esc・外側クリックで閉じます。削除の確認ボタンは赤い「削除」です。
- 既存の「表面」A4縦様式を維持し、1枚に1〜9件を記入。日本語フォントを埋め込んだ選択可能な文字のPDF。
- PDFはブラウザ内で生成し、端末へ直接ダウンロード。印刷画面やGAS・Driveを経由しません。
- 入力・日時前後・人数の検査。用紙に収まらない長文やフォント未対応文字は、切り取らず修正を案内。
- メール・活動通知のUIは現在非表示。
- 任意の責任者情報保存、下書き保存、最近10件の作成履歴。履歴にはPDF本体を保存しません。

用紙の日時欄は元の様式どおり**月日・曜日のみ**です。年を明記する必要がある利用は備考等で補ってください。使用日をまたぐ時間帯は未対応です。

## 個人情報・保存の扱い

- 元の責任者氏名・学籍番号・電話番号・メール宛先は、初期値にも公開アセットにも引き継いでいません。
- アプリは入力情報や作成PDFを外部サーバーに送信しません。ログイン・解析・広告・外部フォント通信はありません。
- 保存は初期状態でオン。学生責任者情報と下書きは**別々にオフへ変更**でき、設定は次回も維持されます。学生責任者情報の保存をオフにしたまま下書きを保存しても、氏名等は保存しません。入力途中の内容も自動保存するため、共用端末では入力前にオフにしてください。
- 保存先は同じブラウザ・同じサイトの`localStorage`です。暗号化・パスワード保護はありません。共用端末では保存しないでください。
- 「保存・履歴」内の「保存データを削除」で学生責任者・下書き・履歴を削除し、自動保存をオフにします。再読込後もオフを維持するための設定だけが残ります。ダウンロード済みPDFは別途削除が必要です。
- URL（ホスト名・ポート）、ブラウザ、端末を変えると保存内容は引き継がれません。Google同期・メンバー制限は未実装です。
- ブラウザ自身のオートフィル／OSの同期機能は、このアプリとは別の設定です。

## スマホ実機からローカル確認する場合

上記の`127.0.0.1`はPC自身のアドレスのため、そのままスマホからは開けません。初期状態では安全のためPC内にのみ公開します。

同じ信頼できるWi-Fiで試す場合だけ、初期サーバーを停止し、プロジェクトのフォルダで次を実行します。

```powershell
$env:HOST = '0.0.0.0'
node tools/serve.mjs
```

PCのIPv4アドレスを調べ、スマホで`http://PCのIPv4アドレス:4173`を開きます。Windowsファイアウォールの許可が必要な場合は信頼できるプライベートネットワークだけに限定してください。**同じネットワークからページ・教室写真にアクセス可能**になりますが、入力情報は各端末内に留まります。試用終了後はサーバーを停止してください。

## 開発・再ビルド

Node.js 24、pnpm 11.28.5を使用。通常のWebアプリ動作にPython・Office・GASは不要です。

```text
pnpm install --frozen-lockfile
pnpm test
node tools/test_pdf.mjs
pnpm build
pnpm start
```

`pnpm`未導入なら、Node.jsの環境で`npm install -g pnpm@11.28.5`を実行してから使用できます。

- 開発サーバー：`pnpm dev`（ビルド済みサーバーと同じ4173番のため、先に片方を止めます）。
- ソース変更後は`pnpm build`してブラウザを再読み込みします。
- [ビルド処理](<tools/build.mjs>)はコンパイラの一時ファイルを作業フォルダ内に限定します。
- 以前の制限環境で作成したローカルpnpmストアとの不一致が出た場合だけ、`pnpm install --store-dir .pnpm-store --ignore-scripts`で同じストアを指定してください。新しい環境では通常のインストールで構いません。

### ブラウザ自動テスト

ビルド後、別の画面で`pnpm start`を実行した状態で、次を実行します。

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.playwright"
pnpm exec playwright install chromium
pnpm test:e2e
```

PC／320〜768pxモバイル表示、各端末幅でのPDF1件・9件、プレビュー連動、写真の横スクロール・拡大、独立カード、端末内保存・復元・削除、保存同意、長文拒否、外部通信の不在を検査します。モバイル検査はChromiumのエミュレーションであり、Android実機のOS保存ダイアログの確認ではありません。

## 写真と資料

- 既存写真16点を原本のまま保管し、ROOMLISTの教室写真148点を全収録。配布用164点は合計約2.92MiBのWebPです。設備ラック等の写真も含め、フロア図・記号は写真ギャラリーから除外しています。
- PDFだけにあった21A・22H・33Jと、指定された72A・72BCを追加し、全42教室。室内写真あり37／42室。**22A・22F・72D・72A・72BCは写真なし**。72A・72BCの定員は未提供のため空欄です。
- 定員は2025年9月のROOMLIST一覧表による参考情報。個別ページとの相違は出典台帳に記録しました。現在の定員・設備・利用可否は大学に確認してください。
- 詳細：[出典・照合結果](<docs/source-audit.md>)、[写真出典台帳](<public/data/photo-sources.json>)、[教室データ](<public/data/rooms.json>)。
- 抽出原本の保管先：[既存写真](<assets/source-photos/xlsx/>)／[PDF内の原画像](<assets/source-photos/pdf/>)。これらはローカル保管用で、Web配布には含めません。
- PDF用紙・フォント・再生成の注意：[PDF実装資料](<docs/pdf-template.md>)。
- フォントはNoto Sans JP（SIL OFL 1.1）。[ライセンス](<public/fonts/OFL.txt>)を同梱しています。

写真・原資料の権利は元の権利者にあります。**学外公開前に掲載・再配布の可否、人物が写る既存写真の扱いを管理者が確認してください。**

## 写真を追加・公開する（管理者PC専用）

1. [管理画面.cmd](<管理画面.cmd>)を起動し、http://127.0.0.1:4174 を開きます。
2. 教室を選び、写真をドラッグ＆ドロップするか複数選択します。縦横比を保って圧縮し、写真の位置情報・元ファイル名等を公開データへ引き継ぎません。
3. 「追加」を押すと、このPCの教室データと画像が更新されます。
4. [写真を公開.cmd](<写真を公開.cmd>)を起動して確認すると、検査・ビルド・GitHubへの反映・公開処理の開始まで進みます。反映状況は[Actions](https://github.com/IZUisMe/classroom-reservation/actions)で確認できます。

管理画面はPC内にのみ接続を受け付け、公開サイトには投稿APIや認証トークンを置きません。スマホ利用者・一般閲覧者は写真を投稿できません。新しく追加する写真の権利や人物の写り込みは、公開前に管理者が確認してください。

詳しい操作・制限：[写真管理ガイド](<docs/photo-admin.md>)。

### 教室データの構成

SQL等のデータベースサーバーは使用せず、Gitで履歴管理するJSON＋画像ファイルです。

- [教室一覧](<public/data/rooms.json>)：アプリが読む統合済みの教室・写真ギャラリー。
- [追加教室](<public/data/custom-rooms.json>)：72A・72BC等、元資料にない教室。
- [管理者追加写真](<public/data/admin-photos.json>)：管理画面から追加した画像と教室IDの対応。
- [写真出典](<public/data/photo-sources.json>)：原資料・管理者追加の出典、ハッシュ、寸法。
- 画像の保管先：`public/images/rooms/`。

原資料から再生成しても、追加教室・管理者写真は最後にマージされます。再生成・公開と管理画面での追加は同時実行せず、作業を終えてから次へ進めてください。
