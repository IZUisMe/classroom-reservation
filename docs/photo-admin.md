# 教室写真の追加（管理者PC専用）

## 起動と追加

1. [管理画面.cmd](<../管理画面.cmd>)をダブルクリックします。
2. **http://127.0.0.1:4174** をChromeで開きます。
3. 教室と写真の種類を選びます。
4. 写真を複数選択するか、選択エリアへドラッグ＆ドロップします。
5. プレビューを確認し、「追加」を押します。写真ごとに室内／外観を変更できます。
6. 追加結果を確認し、公開アプリを再ビルドします。

```text
pnpm build
```

ローカルの公開アプリを再読み込みすると写真が反映されます。GitHub Pagesを更新する場合は、[写真を公開.cmd](<../写真を公開.cmd>)を実行し、確認で **Y** を選びます。画面に **「公開が完了しました。管理者追加写真 ○ 枚の反映を確認しました。」** と表示されるまで、ウィンドウを閉じないでください。コマンドは検査・送信・公開完了待ち・実際の画像の一致確認まで行います。途中で止まった場合はエラーが画面に残り、追加済みの写真はこのPCに保存されたままです。この管理画面にはGitHubへのpushボタン、投稿用トークン、外部アップロード先を置いていません。

停止は起動用ウィンドウで **Ctrl+C**。Node.jsがPATHにない場合、この端末ではDeepSeek Harness付属Node.jsを候補とします。管理GUI自体には追加のnpm依存・ビルドは不要です。

## 写真の制限

- 元画像：JPG・PNG・WebP。1枚20MBまで、一辺16384px以内・4000万画素以内。
- 一度の選択：30枚まで。変換・送信は1枚ずつ処理します。
- ブラウザ内で縦横比を保ち、拡大せず最大1440×1080の静止WebPへ変換します。
- ブラウザのCanvasを経由するため、元ファイル名・EXIF・位置情報・XMP等を保存しません。ファイル名は画面内の確認表示にのみ使用します。
- サーバーはWebPのみ受け付け、4MB／画像、本文6MB、RIFF/WEBP識別子・チャンク・寸法を検証します。メタデータやアニメーションのチャンクは拒否します。
- 追加失敗が表示された写真は、一度一覧から外してから選び直してください。追加済みの写真を再度選択すると、別写真として重複追加されます。

## どこに保存するか

管理用サーバーは**正本の公開用データ**を更新します。ビルド済みフォルダを直接書き換える方式ではありません。

- 管理写真台帳：`public/data/admin-photos.json`（schemaVersion 1）
- 写真：`public/images/rooms/admin-UUID.webp`
- 教室ギャラリー：`public/data/rooms.json`
- 写真出典台帳：`public/data/photo-sources.json`

写真の出典は「管理者追加」です。元資料に写真がなかった記録は履歴として残し、追加画像を独立したavailableレコードとして登録します。既存の代表写真は置き換えず、代表写真が空欄だった場合だけ追加画像を代表にします。

データ再生成時も、管理写真台帳を統合する処理を通して管理写真を維持してください。再適用は冪等で、同じ台帳の読み込みによってギャラリーが重複することはありません。

## 安全性と公開範囲

- 管理者とは、この管理者PCにログインできる同一OSユーザーです。ログインフォームや共有の管理者パスワードは設けていません。
- 管理用サーバーは**127.0.0.1:4174にだけ待受**します。`HOST`や`PORT`環境変数は参照せず、LAN・インターネットへ公開しません。
- 公開GitHub Pagesには管理APIがありません。管理画面のHTML・JSも公開用ビルドには含めません。
- Host、更新リクエストのOrigin、起動ごとのランダムCSRFトークンを検証します。CORSを許可せず、画像やデータを外部サーバーへ送信しません。
- ブラウザに配信するファイルは管理画面のHTML・JS・CSSのみです。任意のローカルファイルや回復記録を配信しません。
- 写真に人物や機密情報が写る場合の掲載可否は、管理者が追加前に確認してください。付加情報を除去しても、写真の画素に写った文字や顔は消えません。

## 更新の整合性

画像と3つのJSONの更新は、単一書込ロックと回復用記録を使って処理します。途中で書込に失敗した場合は元のJSONへ戻し、新しい画像も削除します。処理中にサーバーが終了した場合は、次の起動時に回復します。回復用記録は管理画面の作業用状態ディレクトリ内で、Web配信しません。

- 管理用サーバーで写真追加中に、別のデータ再生成処理を同時に実行しないでください。再生成する場合は先に管理用サーバーを停止してください。
- 回復に失敗したというエラーが出た場合は、書込権限・空き容量を確認し、管理用サーバーを再起動してください。回復用記録を削除すると元に戻せなくなるため、勝手に消さないでください。
- ロックが残った場合、元のプロセスが終了していれば次の起動で回収します。PIDが再利用される等で更新中と表示され続ける場合は、すべての管理用サーバーを停止してから管理者が状態を確認してください。

## 検証

[管理API・整合性テスト](<../tests/admin.test.mjs>)は、一時的な42教室fixtureを作成して検証し、本物の公開データを変更しません。

```text
node --test tests/admin.test.mjs
```

既存のPlaywright／Chromiumが利用できる開発環境では、GUIの変換・複数画像追加も実行できます。

```powershell
$env:RUN_ADMIN_BROWSER_TEST = '1'
node --test tests/admin.test.mjs
```

テスト用サーバーだけは空いているループバックポートを使用し、テスト終了時に停止します。通常の管理画面は4174固定です。
